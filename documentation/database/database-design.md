# تصميم قاعدة البيانات

## النطاق والمبادئ

هذا التصميم خاص بالمرحلة 1 فقط، ومخصص لـ MySQL 8.4 LTS باستخدام InnoDB و`utf8mb4` وPDO، دون ORM. لا ينشئ هذا المستند جداول أو ينفذ Migrations.

النظام مركزي ويدير مواقع مستقلة. كل سجل يخص موقعاً يرتبط بـ`website_id`، ولا توجد حسابات عملاء أو جدول `admin_users`. بيانات دخول المسؤول تُقرأ من `ADMIN_USERNAME` و`ADMIN_PASSWORD_HASH` في بيئة التشغيل؛ يولد الهاش بـ`password_hash()` ويتحقق منه بـ`password_verify()`، ولا تحفظ كلمة المرور في قاعدة البيانات أو Git.

## الجداول والعلاقات

- `websites`: هوية الموقع وحالته واللغة والاتجاه والقالب النشط وإصداره.
- `domains`: الدومينات الأساسية والبديلة؛ `domain` مطبع وفريد عالمياً، و`is_primary` يحدد الدومين الأساسي لكل موقع.
- `templates`: تسجيل Metadata القوالب فقط؛ الملفات في filesystem.
- `website_template_settings`: إعدادات كل موقع مع كل قالب، مع سجل محفوظ للتبديل والتراجع.
- `pages`: صفحات الموقع، وقيد `UNIQUE(website_id, slug)`.
- `sections`: أقسام الصفحات ومحتواها المرن في JSON.
- `media`: Metadata للملفات فقط؛ الملفات الثنائية خارج MySQL.
- `navigation_menus` و`navigation_items`: قوائم الموقع وعناصرها.
- `website_settings`: إعدادات الموقع غير العلائقية.
- `schema_migrations`: سجل تنفيذ الترحيلات.

`websites` هو جدول الجذر وله `id` فقط. الجداول المالكة للموقع تحتوي `website_id`، وكل جدول مالك يحتاج إلى مرجع مركب يعرّف `UNIQUE(website_id, id)`. عند الربط بين جداول مملوكة للموقع تستخدم الصيغة `FOREIGN KEY (website_id, parent_id) REFERENCES parent_table(website_id, id)`، أما الربط المباشر بالموقع فيستخدم `FOREIGN KEY (website_id) REFERENCES websites(id)`.

## الدومينات والـ slugs

يُحوّل الدومين إلى lowercase، تزال النقاط النهائية و`www.`، ويُقبل hostname فقط دون scheme أو path أو query. يمنع `UNIQUE(domain)` ربط الدومين بموقعين. لضمان دومين أساسي واحد كحد أقصى لكل موقع، يحتوي `domains` على العمود المولد `primary_website_id` بالتعبير `CASE WHEN is_primary = 1 THEN website_id ELSE NULL END` وقيد `UNIQUE(primary_website_id)`. هذا القيد لا يضمن وجود دومين أساسي؛ لذلك يفرض `WebsiteService` أن يمتلك الموقع دوميناً أساسياً قبل تفعيله. إنشاء الموقع وتعيين الدومين الأساسي والتفعيل يتم داخل Database Transaction، ولا يسمح حذف الدومين الأساسي أو إلغاء تعيينه إذا كان سيترك موقعاً مفعلاً دون دومين أساسي. لا يُنسخ الدومين الأساسي إلى `website_settings`.

يطبع slug قبل التخزين وفق سياسة التطبيق: إزالة المسافات الزائدة، صيغة URL آمنة، ورفض المسارات المحجوزة مثل `admin` و`api` و`assets`. يسمح نفس slug في موقعين مختلفين. السجل المحذوف منطقياً يحتفظ بالـ slug؛ لذلك لا يعاد استخدامه تلقائياً، ويمكن استخدام قيمة تاريخية أو إعادة التسمية وفق سياسة التطبيق.

## العزل وJSON

لا تكفي مفاتيح `page_id` أو `media_id` منفردة. لذلك تربط الأقسام والقوائم وعناصرها بالموقع وبالسجل الأب عبر مفاتيح مركبة. أما مراجع الوسائط داخل JSON فلا تفرض لها MySQL سلامة مرجعية؛ يجب أن يحتوي JSON على معرفات media معروفة، وأن يتحقق `SectionService` من ملكية كل معرف للموقع قبل استدعاء Repository. عند الحاجة إلى علاقات كثيرة، يُفضّل جدول mapping علائقي في قرار لاحق بدلاً من JSON.

## القوالب والتبديل

القالب النشط وإصداره في `websites.template_id` و`websites.template_version` فقط. تحفظ إعدادات القالب في `website_template_settings`. يضاف `active_template_id` مولد بالتعبير `CASE WHEN deleted_at IS NULL THEN template_id ELSE NULL END` وقيد `UNIQUE(website_id, active_template_id)`؛ لذلك يسمح بالسجلات التاريخية المحذوفة منطقياً ويمنع أكثر من إعداد نشط للموقع والقالب. لا يُحذف المحتوى أو الصفحات أو الوسائط عند التبديل.

## الوسائط الافتراضية

عند إنشاء موقع، تنسخ ملفات `default-media` إلى مساحة تخزين الموقع، ثم ينشئ التطبيق سجلاً مستقلاً لكل ملف في `media` مع `website_id` الجديد. لا توجد سجلات media مشتركة بين المواقع.

## الحذف والاحتفاظ

حذف الموقع يكون أرشفة منطقية (`deleted_at`) مع منع عرضه، ولا تحذف السجلات التابعة تلقائياً. حذف الصفحة أرشفة، وتحافظ عناصر navigation عليها أو تُعلّم كرابط غير صالح قبل حذفها. حذف media يكون محظوراً إذا كان مرجعاً علائقياً، ويحتاج JSON إلى فحص خدمة قبل الحذف. لا تحذف القوالب المسجلة إذا كانت مستخدمة؛ تُعطّل. `schema_migrations` لا يحذف منه سجل ناجح. إعدادات الموقع كلها في جدول key/value موحد (`setting_key`, `setting_value JSON`) دون أعمدة branding موازية.

## الأمان والأداء

تستخدم الحسابات الإدارية متغيرات البيئة، وتُحمى ملفات `.env` والنسخ الاحتياطية. تستخدم طبقة Repository PDO وPrepared Statements. الفهارس موثقة في `database-indexes.md`، وأهمها domain، وقيود slug المركبة، واسترجاع الصفحات المنشورة والأقسام والقوائم.
